# Elysia Health API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a minimal Bun and TypeScript Elysia server with a tested `GET /health` endpoint.

**Architecture:** Use the official Elysia generator in a temporary sibling directory only to obtain the current starter configuration without overwriting the approved documentation already in the target folder. The application remains a single exported Elysia instance; it listens on port 3000 only when executed directly, allowing tests to call `app.handle()` without opening a socket.

**Tech Stack:** Bun, TypeScript, Elysia, Bun test runner

**Spec:** `elysia-api-package-app/docs/superpowers/specs/2026-08-26-elysia-health-api-design.md`

## Global Constraints

- The project root is `elysia-api-package-app`.
- The only API route is `GET /health`.
- A successful response is HTTP `200` with JSON `{ "status": "ok" }`.
- Do not add a database, ORM, authentication, OpenAPI, CORS, telemetry, Docker, feature modules, or service abstractions.
- Use the global Codex Skill configuration; do not install project-local Skills, hooks, or commands.
- Do not initialize Git. The enclosing workspace is not a Git repository.

## File Map

- Create `elysia-api-package-app/package.json`: package metadata, dependencies, and `dev`, `start`, `check`, and `test` scripts.
- Create `elysia-api-package-app/tsconfig.json`: current generator-compatible TypeScript configuration.
- Create `elysia-api-package-app/bun.lock`: dependency lock generated by `bun install`.
- Create `elysia-api-package-app/.gitignore`: generated artifacts and local environment exclusions.
- Create `elysia-api-package-app/src/index.ts`: exported Elysia application, health route, and direct-run listener.
- Create `elysia-api-package-app/src/index.test.ts`: health route contract test.
- Preserve `elysia-api-package-app/docs/`: approved design and implementation plan.

### Task 1: Scaffold and implement the health API

**Files:**

- Create: `elysia-api-package-app/package.json`
- Create: `elysia-api-package-app/tsconfig.json`
- Create: `elysia-api-package-app/bun.lock`
- Create: `elysia-api-package-app/.gitignore`
- Create: `elysia-api-package-app/src/index.ts`
- Test: `elysia-api-package-app/src/index.test.ts`
- Preserve: `elysia-api-package-app/docs/`

**Interfaces:**

- Consumes: Bun runtime and the `Elysia` class from the `elysia` package.
- Produces: exported `app: Elysia`, `GET /health`, and direct execution on port `3000`.

- [ ] **Step 1: Generate a current Elysia starter as a temporary reference**

Run from the workspace root:

```powershell
bun create elysia .elysia-health-reference
```

Expected: exit code `0`; `.elysia-health-reference` contains the current Elysia starter. Do not copy its example route blindly and do not alter `elysia-api-package-app/docs/`.

- [ ] **Step 2: Create the project configuration from the generator baseline**

Use the generated `package.json`, `tsconfig.json`, and `.gitignore` as the compatibility baseline. Set the project name to `elysia-api-package-app` and ensure `package.json` exposes these scripts:

```json
{
  "scripts": {
    "dev": "bun run --watch src/index.ts",
    "start": "bun run src/index.ts",
    "check": "tsc --noEmit",
    "test": "bun test"
  }
}
```

Keep only dependencies required by the generated Elysia TypeScript starter. Do not add plugins.

- [ ] **Step 3: Install the declared dependencies**

Run:

```powershell
bun install --cwd elysia-api-package-app
```

Expected: exit code `0`; `elysia-api-package-app/bun.lock` is created and no dependency outside the starter set is added.

- [ ] **Step 4: Write the failing health endpoint test**

Create `elysia-api-package-app/src/index.test.ts`:

```typescript
import { describe, expect, it } from 'bun:test'
import { app } from './index'

describe('GET /health', () => {
  it('returns the service health', async () => {
    const response = await app.handle(
      new Request('http://localhost/health')
    )

    expect(response.status).toBe(200)
    expect(await response.json()).toEqual({ status: 'ok' })
  })
})
```

- [ ] **Step 5: Run the test and verify the red state**

Run:

```powershell
bun test --cwd elysia-api-package-app src/index.test.ts
```

Expected: FAIL because `src/index.ts` does not yet export the required `app` with `GET /health`. A failure caused only by a missing dependency means Step 3 is incomplete and is not an acceptable red state.

- [ ] **Step 6: Implement the minimal Elysia application**

Create `elysia-api-package-app/src/index.ts`:

```typescript
import { Elysia } from 'elysia'

export const app = new Elysia()
  .get('/health', () => ({ status: 'ok' }))

if (import.meta.main) {
  app.listen(3000)
  console.log(`Elysia is running at http://${app.server?.hostname}:${app.server?.port}`)
}
```

- [ ] **Step 7: Run the focused test and verify the green state**

Run:

```powershell
bun test --cwd elysia-api-package-app src/index.test.ts
```

Expected: one test passes with zero failures.

- [ ] **Step 8: Run full static and test verification**

Run:

```powershell
bun run --cwd elysia-api-package-app check
bun run --cwd elysia-api-package-app test
```

Expected: both commands exit `0`; TypeScript reports no errors and all tests pass.

- [ ] **Step 9: Perform an HTTP smoke test**

Start the server:

```powershell

```

From another process, request:

```powershell

```

Expected response:

```json
{"status":"ok"}
```

Stop the server after the response is verified.
